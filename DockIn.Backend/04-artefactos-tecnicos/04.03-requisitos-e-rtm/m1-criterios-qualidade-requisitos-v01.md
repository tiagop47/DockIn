# Critérios de Qualidade dos Requisitos

## 1. Objetivo

Este documento define os critérios utilizados pelo grupo G02 para avaliar
a qualidade dos requisitos funcionais e não funcionais do sistema.

Os critérios aqui definidos são aplicados individualmente a cada requisito
através da Checklist de Aprovação dos Requisitos durante a milestone `m2`.

## 2. Critérios de Qualidade

| Critério | Definição | Condição para cumprimento |
|---|---|---|
| Correção | O requisito representa corretamente uma necessidade, regra ou restrição aplicável ao sistema. | Está alinhado com as fontes que lhe dão origem e não contém informação funcional ou factual incorreta. |
| Clareza | O requisito é redigido de forma compreensível para os intervenientes do projeto. | O comportamento, condição ou resultado pretendido pode ser compreendido sem necessidade de interpretação adicional relevante. |
| Completude | O requisito contém a informação necessária para compreender e verificar o comportamento pretendido. | Não faltam condições, entradas, resultados, restrições ou exceções essenciais à sua interpretação e verificação. |
| Consistência | O requisito é compatível com os restantes requisitos e com os artefactos aprovados do projeto. | Não existem contradições com outros requisitos, com o âmbito aprovado ou com decisões formalizadas. |
| Necessidade | O requisito corresponde a uma necessidade efetiva do sistema. | Existe uma origem ou justificação identificável para a sua inclusão no sistema. |
| Viabilidade | O requisito pode ser concretizado no contexto do projeto. | A sua implementação é compatível com o âmbito, as tecnologias, os recursos e o tempo disponíveis. |
| Verificabilidade | O cumprimento do requisito pode ser determinado objetivamente. | Existe pelo menos uma forma concreta de teste, inspeção, demonstração ou outra verificação objetiva. |
| Rastreabilidade | O requisito pode ser relacionado com a sua origem e com os artefactos que dele resultam. | Possui identificação única e permite estabelecer as relações de rastreabilidade aplicáveis. |
| Singularidade | O requisito expressa uma única obrigação principal. | Não agrega obrigações independentes que devam ser especificadas como requisitos distintos. |
| Ausência de ambiguidade | O requisito admite uma interpretação única e suficientemente objetiva. | Evita termos vagos, subjetivos ou indeterminados sem critério de interpretação ou medição. |
| Independência da solução | O requisito descreve a necessidade ou comportamento pretendido sem impor desnecessariamente uma solução de implementação. | Não determina tecnologia, arquitetura ou mecanismo técnico específico, salvo quando tal constitua uma restrição aprovada. |

## 3. Aplicação e Resultado

Cada requisito é avaliado individualmente segundo todos os critérios definidos
neste documento através da Checklist de Aprovação dos Requisitos.

Para cada critério é utilizado exclusivamente um dos seguintes resultados:

- `Cumpre`;
- `Não cumpre — <justificação objetiva>`;
- `Não aplicável — <justificação>`.

O Resultado Final de cada requisito utiliza exclusivamente:

- `Aprovado`;
- `Não aprovado`.

Um requisito apenas pode obter o Resultado Final `Aprovado` quando todos os
critérios aplicáveis se encontram classificados como `Cumpre`.

Quando um critério for classificado como `Não aplicável`, a respetiva
justificação deve indicar objetivamente por que motivo esse critério não se
aplica ao requisito em avaliação.
